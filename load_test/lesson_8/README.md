# Разделение монолита на сервисы

За ооснову микро сервисной архитектуры будет взята EDA (Event Driven Architecture) + gRPC

При разделения монолита на микро сервисы - необходимо каждую сущность вынести в отдельный микро сервис.

Возьмем за правило - каждый микро сервис обладает своей БД.

### Что было сделано:

- Разработал микросервис Event-getaway - для взаимодействия микросервисов
- Из монолита "Otus" вынес функционал диалогов в отдельный микросервис
- Настроил события для каждого микросервиса

### Плюсы такого подхода (EDA+gRPC)

- Слабая связанность сервисов
- Позволяет горизонтально масштабироваться
- Повышает отказоустойчивость приложения
- Ассинхронные вызовы сервисов (т.е. обеспечивают низкую задержку ответов)
- Межпроцессорное взаимодейтсвие (за счет gRPC - минимальные сетевые расходы)

## Развертывание

Открываем терминал на нашем сервере и в cli выполняем команды согласно инструкции.

1) Скачиваем 3 репозитория (otus, ms_dialog, event-getaway)

```
git clone https://github.com/proweb-zone/event-getaway.git

git clone https://github.com/proweb-zone/otus_social_network.git

git clone https://github.com/proweb-zone/ms_dialog.git
```
2) Переходим в проект event-getaway и запускаем docker контейнер

```
cd /my_path/event-getaway/
docker compose up -d
```
2) Переходим в проект otus_social_network и запускаем docker контейнер и делаем миграцию БД

```
#  переходим в проект
cd /my_path/event-getaway/

# поднимаем docker
docker compose up -d

# проводим миграцию БД
make migration-up
```
3) Переходим в проект ms_dialog и запускаем docker контейнер и делаем миграцию БД

```
#  переходим в проект
cd /my_path/ms_dialog/

# поднимаем docker
docker compose up -d

# проводим миграцию БД
make migration-up
```
Далее делаем все через Postman

4) В корне микросервиса otus_social_network берем postman_json_collection и загружаем в postman
5) Авторизуемся и сохраняем токен авторизации (Bearer Token)
6) Регистрируем двух пользователей
7) Добавляем друг друга друзья
8) И отправляем друг другу сообщение

По итогу мы должны получить функционал отправки сообщения другу и получения диалогов работающих на микросервисной архитектуре. Где пользователи и весь другой функционал храниться в другом микросервисе, а за взаимодействие отвечает микросервис менеджер событий event-getaway
